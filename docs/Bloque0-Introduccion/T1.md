## Prerequisites

- **Formal prerequisite**: Digital Design (LIIE program).
- **Programming**: basic C proficiency; comfortable with compiling from the command line.
- **Electronics**: breadboard prototyping, safe power practices, using a multimeter; ESD awareness.
- **Tools readiness**: laptop capable of running the Pico SDK toolchain (CMake, GDB, OpenOCD), VS Code, and Python for plotting; known-good USB data cable(s).

## Course Text

- Raspberry Pi Pico C/C++ SDK documentation and RP2040 Datasheet (registers, GPIO, timers, PWM, ADC, UART, PIO, DMA, multicore).
- WARD, Hubert Henry. *C Programming for the PIC Microcontroller: Demystify Coding*. Apress, 2019.
- BARRETT, Steven F. & PACK, Daniel J. *Microchip AVR® Microcontroller Primer: Programming and Interfacing*, 3rd ed. Morgan & Claypool, 2019.
- PAREDES, Ernesto M. *Curso práctico para programación de AVR*. Alfaomega, 2017.

**Late & makeup policy**

| Item                | Policy                                                                                                          |
| ------------------- | --------------------------------------------------------------------------------------------------------------- |
| Late submissions    | −20% penalty (grade capped at 8.0) if submitted within **7 days** of the deadline; after that, not accepted except for justified, documented cases. |
| Submission format   | All deliverables in **PDF**, following the provided rubric, on the designated platform. Wrong format or platform = **−1 point** on that item. |
| Exams               | The late-submission penalty does **not** apply to exams; an unjustified absence on an exam = **0**. With a justified, documented absence, the exam is rescheduled close to the original date. |
| Extensions          | May be requested **by email before the deadline** for justified absences.                                       |
| Regrade window      | Written request within **7 business days** of grade release. Forfeited with more than 5 unjustified absences.   |

**Exam policies**

| Item                  | Policy                                                                                                        |
| --------------------- | ------------------------------------------------------------------------------------------------------------- |
| Exams 1 & 2 format    | **Practical, take-home**: the specification is handed out in a prior session and solved outside class. On the scheduled date, students present and defend: live demo, questions on design decisions, and optionally a live modification of the submitted code. |
| Exam 3 format         | **Written, theoretical, individual, in-class**. Topic list provided at least one week in advance. One **handwritten** reference sheet allowed. |
| Submission            | Practical exam materials (code, measurement evidence, report) are uploaded **before** the presentation session. The submitted version is the one graded — no same-day modifications. |
| Grading criteria      | Specification compliance, quality of measurement evidence, and oral defense. An incomplete but well-measured and well-justified solution scores better than a functional one without evidence or explanation. |
| Authorship            | Documentation and support tools may be consulted. Authorship is verified during the defense: a student who cannot explain or modify their own code does **not** pass the exam. |

**Attendance**

| Item                  | Policy                                                                                                        |
| --------------------- | ------------------------------------------------------------------------------------------------------------- |
| Justified absences    | Medical, serious family matters, legal appointments, force majeure. Documentation must be submitted within **7 business days** of the absence. |
| Unjustified absences  | Do not directly affect the grade, but accumulating **more than 5** forfeits the right to grade reviews.        |

## Modules

| Module                                        | Topics                                                                                           | Sessions |
| --------------------------------------------- | ------------------------------------------------------------------------------------------------ | -------- |
| **M0 — Setup & Toolchain**                    | ESD safety, Pico SDK / CMake / GDB / OpenOCD installation, first builds                          | 1        |
| **M1 — Bare-Metal I/O & Timing**              | Register-level programming, GPIO & bitwise ops, debouncing, FSMs, SysTick, IRQ latency, HW timers | 2–6      |
| **M2 — Serial Communication & Scheduling**    | UART from scratch (ISR RX/TX, ring buffers, CLI), cooperative time-slicing, UART-based debugging  | 7–9      |
| **M3 — Analog Interfacing**                   | PWM (LEDs, servos, DC motors), ADC & sampling theory, filtering & telemetry, sensor linearization | 10–14    |
| **M4 — PIO & DMA**                            | PIO architecture, generation & capture, PIO+C integration, DMA to PWM/PIO/UART                    | 15–20    |
| **M5 — Performance, Robustness & Production** | ISR profiling, watchdog/brown-out, low power, EMC, multicore, boot & memory, unit testing         | 21–26    |
| **M6 — Capstone: Micromouse**                 | Final integration, arena mode, technical inspection, competition                                  | 27–29    |
