    Syllabus

    Course Meeting Times

    Lectures: 2 sessions / week, 2 hours / session

    Group Days Time
    A Monday & Wednesday 17:00 - 19:00
    B Tuesday & Thursday 17:00 - 19:00

    Room: J-144 (Electronics Laboratory)

    Prerequisites

    • Formal prerequisite: Digital Design (LIIE program).
    • Programming: basic C proficiency; comfortable with compiling from the command line.
    • Electronics: breadboard prototyping, safe power practices, using a multimeter; ESD awareness.
    • Tools readiness: laptop capable of running the Pico SDK toolchain (CMake, GDB, OpenOCD), VS Code, and Python for plotting; known-good USB data cable(s).

    Course Text

    • Raspberry Pi Pico C/C++ SDK documentation and RP2350 Datasheet (registers, GPIO, timers, PWM, ADC, UART, PIO, DMA, multicore).
    • WARD, Hubert Henry. C Programming for the PIC Microcontroller: Demystify Coding. Apress, 2019.
    • BARRETT, Steven F. & PACK, Daniel J. Microchip AVR® Microcontroller Primer: Programming and Interfacing, 3rd ed. Morgan & Claypool, 2019.
    • PAREDES, Ernesto M. Curso práctico para programación de AVR. Alfaomega, 2017.

    Supplementary references

    • IEEE RAS (Robotics & Automation Society) official magazine: https://www.ieee-ras.org/publications/ram
    • IEEE Xplore article repository: https://ieeexplore.ieee.org/Xplore/home.jsp
    • IEEE article writing guide: https://site.ieee.org/sb-luz/2017/01/20/describir-tu-proyecto-con-el-modelo-ieee-para-articulos/
    • IEEE citation guide: https://ieeeauthorcenter.ieee.org/wp-content/uploads/IEEE-Reference-Guide.pdf

    Late & makeup policy

    Item Policy
    Late submissions −20% penalty (grade capped at 8.0) if submitted within 7 days of the deadline; after that, not accepted except for justified, documented cases.
    Submission format All deliverables in PDF, following the provided rubric, on the designated platform. Wrong format or platform = −1 point on that item.
    Exams The late-submission penalty does not apply to exams; an unjustified absence on an exam = 0. With a justified, documented absence, the exam is rescheduled close to the original date.
    Extensions May be requested by email before the deadline for justified absences.
    Regrade window Written request within 7 business days of grade release. Forfeited with more than 5 unjustified absences.

    Exam policies

    Item Policy
    Exams 1 & 2 format Practical, take-home: the specification is handed out in a prior session and solved outside class. On the scheduled date, students present and defend: live demo, questions on design decisions, and optionally a live modification of the submitted code.
    Exam 3 format Written, theoretical, individual, in-class. Topic list provided at least one week in advance. One handwritten reference sheet allowed.
    Submission Practical exam materials (code, measurement evidence, report) are uploaded before the presentation session. The submitted version is the one graded — no same-day modifications.
    Grading criteria Specification compliance, quality of measurement evidence, and oral defense. An incomplete but well-measured and well-justified solution scores better than a functional one without evidence or explanation.
    Authorship Documentation and support tools may be consulted. Authorship is verified during the defense: a student who cannot explain or modify their own code does not pass the exam.

    Attendance

    Item Policy
    Justified absences Medical, serious family matters, legal appointments, force majeure. Documentation must be submitted within 7 business days of the absence.
    Unjustified absences Do not directly affect the grade, but accumulating more than 5 forfeits the right to grade reviews.

    How to submit

    Once, at the start of the course (due in session 2)

    1. On GitHub, open the course template repo → Use the template → name it lablog-<studentID>-embedded1 (e.g. lablog-190123-embedded1). Public repo.
    2. Enable GitHub Pages: Settings → Pages → Source: GitHub Actions. The included workflow builds and publishes your site on every push to main.
    3. Edit docs/index.md with your name, ID, group and board label. Push. Confirm your site loads at https://<user>.github.io/lablog-<id>/.
    4. Send the repo URL and site URL through the platform. No URL by session 2 = Lab Log entries can't be graded until it exists.

    Every session

    1. Copy docs/sessions/_template.md → docs/sessions/YYYY-MM-DD-sNN.md. Fill in Prediction before you run anything.
    2. Put the session's code in src/sNN_<short_name>/ as a buildable Pico project (own CMakeLists.txt). Commit it.
    3. Do the work. Save captures and photos to docs/images/ using the sNN_ prefix.
    4. Finish the entry. Put the commit hash of the code you documented in the front matter (commit:). Push before the next session starts.
    5. Export the entry to PDF (browser → Print → Save as PDF from your Pages site) and upload it to the platform under the corresponding assignment.

    What counts as submitted

    • The repo is the evidence: the commit must build, images must exist, and git log dates must be consistent with the entry date. If they aren't, the entry is treated as late.
    • Late = after next session start: max grade 8.0 within 7 days, not accepted after (see syllabus).

    Checklist before you push

    • Prediction written with arithmetic, not just a number.
    • Every number in "Predicted vs measured" points to an evidence file that exists in docs/images/.
    • Setup photo has the date card in frame.
    • "What went wrong" has at least one real item.
    • commit: in the front matter matches the code in src/.
    • Disclosure filled in (write "none" if none).
    • Site builds (check the Actions tab is green).

    Be ready to defend it

    Any entry may be discussed in person: expect to explain any line of code, any number, and any capture. Entries you can't explain are graded as if not submitted.
